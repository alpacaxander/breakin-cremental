# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

BreakIn cremental: a breakout-style incremental game in Godot 4.7 (GDScript). Between timed rounds the player buys upgrades and places pieces on a generated board, then plays the round to cash in. Design, status and open risks: `docs/design.md`.

## Commands

Godot is not on PATH; it comes from the Nix dev shell (`nix develop`, or prefix commands with `nix develop -c`).

```sh
godot                                  # open the editor on this project
godot --headless -s tests/test.gd      # rules self-check (game.gd, brick.gd, fx.gd, tuning.gd); prints "ok" or FAIL lines, exits 1 on failure
godot --headless tests/smoke.tscn      # one scripted round through arena.gd; any script error prints. A scene, not -s, so the Game autoload exists
node assets/pixel/gen.mjs              # regenerate every sprite and animation strip in assets/pixel/png/ (needs ImageMagick `magick`)
```

There is no test framework and no lint step. `tests/test.gd` is a plain `SceneTree` script using a `check(ok, msg)` helper; add a line there when a rule changes. The smoke test saves the real `user://save.json` and restores it afterward.

## Architecture

Eight scripts in `src/`, no scenes except `main.tscn`. Everything is built in code.

- **`tuning.gd`** is the single home for every number and table: level layouts (`LEVELS`), brick kinds (`BRICKS`, `ICON_KINDS`), placeable pieces (`PLACEABLES`), and the upgrade web (`UPGRADES`). Changing balance means editing this file only. Keys are shared across tables: a placeable's id doubles as its upgrade id (owned count = `start` + rank), and `ICON_KINDS` must all be `BRICKS` keys. `test.gd` enforces these cross-references.
- **`game.gd`** (autoload `Game`) holds run state (currency, unlocked level, upgrade ranks), save/settings files, and the pure rules: combo window and multiplier, upgrade reveal/cost/buy, derived stats, and `generate(level, seed)` for boards. It has no scene dependencies, which is why `test.gd` can instantiate it headless.
- **`main.gd`** swaps one child at a time between the main menu, `shop.gd` (upgrade web and level select) and `arena.gd` (a round). Signals `play(level)` / `menu` / `done` drive the swaps.
- **`arena.gd`** is one round end to end: placement mode (drag pieces from a tray, R rotates, capacity check), then play mode (ball physics, paddle, combo timer, brick effects, pass-through pieces, spawner), then a result panel. Balls are an inner `CharacterBody2D` class. Brick-kind behaviour lives here in `_damage`, `_effect` and `_pass`, keyed by `kind` string; `brick.gd` only knows shape and look.
- **`brick.gd`** (`Box`) is every physical piece: board bricks, placeables, paddle, walls. It maps `kind` to a still face and optional looping idle strip (`FACE`, `IDLE` tables). Pass-through placeables set `collision_layer = 0` and the arena checks overlap itself.
- **`fx.gd`** plays horizontal animation strips from `assets/pixel/png/anim_<name>.png` as `AnimatedSprite2D` at 2x, slicing by a caller-supplied frame width. One `SpriteFrames` is cached per strip, so a strip must always be played at the same fps.
- **`ui.gd`** builds menu screens (full-rect `ColorRect` plus a centered column) and the settings screen; `theme.tres` styles them.

## Art pipeline

Sprites are pixel art on a 640x360 canvas shown at 2x (nearest filtering, set in `project.godot`). Game-space sizes in `tuning.gd` are 2x the sprite sizes (a 60x24 brick is a 30x12 sprite). All PNGs are generated by `assets/pixel/gen.mjs` and committed; do not hand-edit them. The strip name, frame width and frame count every call site uses must match `docs/animations.md`, and `test.gd` checks that each strip the arena plays slices into the documented frame count. `docs/art-style.md` and `docs/palette.md` describe the lamp look and colours; when the docs and `gen.mjs` disagree, the code wins and the doc gets fixed.

`assets/vector/` is an earlier SVG attempt, excluded from Godot import by `.gdignore` and not used by the game.

## Conventions

- Ponytail style: the smallest working change, and deliberate shortcuts are marked with a `# ponytail:` comment naming the ceiling and the upgrade path. Keep that habit.
- Each script opens with a `##` doc comment saying what it owns; keep those accurate when responsibilities move.
- Capture freed-able nodes in lambdas by instance id (see the spawn tween in `arena.gd`), not by reference.
